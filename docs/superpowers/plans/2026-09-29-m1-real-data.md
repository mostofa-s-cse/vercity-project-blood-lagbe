# M1: Real Data and Request Lifecycle Implementation Plan

> **For agentic workers:** work task by task. Steps use checkbox (`- [ ]`) syntax: tick a box only when the step is done and verified, and add a line to the progress log in `docs/HANDOFF.md`. Read `CLAUDE.md` and `docs/HANDOFF.md` first.

**Goal:** Donors and blood requests are read from the database (not sample data), with a real request lifecycle (Pending, Donor Found, Completed, Cancelled), Redux Toolkit / RTK Query as the client data layer.

**Architecture:** Route handlers under `src/app/api` return DTOs built from Prisma rows; an RTK Query slice (`src/store`) fetches them; screens read from RTK Query hooks. Pure rules (status transitions, remaining time, phone masking, token hashing) live in `src/lib` with tests. Requests made without an account are managed with a one-time manage token.

**Tech stack:** Next.js 16, React 19, Redux Toolkit + RTK Query, Prisma 7 (PostgreSQL), TypeScript (non-strict), node:test.

**Spec / roadmap:** `docs/SPEC-MATCH-PLAN.md` (WP9, WP1, WP2). Target after M1: realistic match ~65%.

## Global constraints
- The app must build and run with **no environment variables** (demo mode): with no database the API answers `503 {"error":"database_not_configured"}` and screens fall back to sample data, exactly as today.
- Emergencies never need an account: list, create, respond and search stay open to signed-out people.
- Every write is checked on the server. No secret in the browser bundle.
- All visible strings in `src/locales/{en,bn}` (identical keys); user-guide text updated where behaviour changes.
- New pure logic: failing test first. New test files go into the `test` script in `package.json`.
- Route files export only HTTP methods and route config.

## Contracts (do not change without updating this file)

### Statuses and transitions
`RequestStatus`: `PENDING`, `DONOR_FOUND`, `COMPLETED`, `CANCELLED`.

| From | Allowed next |
|---|---|
| `PENDING` | `DONOR_FOUND`, `COMPLETED`, `CANCELLED` |
| `DONOR_FOUND` | `PENDING`, `COMPLETED`, `CANCELLED` |
| `COMPLETED`, `CANCELLED` | none (final) |

A first response moves `PENDING` to `DONOR_FOUND` automatically. Responses are accepted only while the request is `PENDING` or `DONOR_FOUND`.

### Who may change a request's status
The person holding its **manage token** (`X-Manage-Token` header), the signed-in **owner** (`userId`), or anyone with permission `panel.requests`.

### DTOs
```ts
interface DonorDto {
  id: string; name: string; bloodGroup: 'A+'|'A-'|'B+'|'B-'|'AB+'|'AB-'|'O+'|'O-';
  area: string; division: string | null; age: number | null; gender: 'Male'|'Female' | null;
  isAvailable: boolean; lastDonationMonths: number | null;
  vehicle: string | null; nearestHospital: string | null;
  phoneMasked: string;            // e.g. "017••••4315", never the full number
  createdAt: string;              // ISO
}
interface RequestDto {
  id: string; area: string | null; problem: string | null;
  patientName: string | null; patientAge: number | null; attendantName: string | null;
  bloodGroup: string; bags: number; bagsPledged: number;   // pledged = number of responses
  place: string; phones: string[];                         // request contact numbers are public by design
  isCritical: boolean; status: RequestStatus; language: 'bn'|'en';
  postText: string; createdAt: string; updatedAt: string; completedAt: string | null;
  responseCount: number;
}
interface ResponseDto { id: string; name: string; createdAt: string; phone?: string } // phone only for the request's manager
```

### Endpoints
| Method and path | Body / query | Success | Errors |
|---|---|---|---|
| `GET /api/donors` | `bloodGroup`, `q` (text in name/area), `available=true`, `page` (1..), `pageSize` (1..50, default 20) | `{ donors: DonorDto[], total, page, pageSize }` | 503 |
| `GET /api/donors/[id]/contact` | | `{ phone }` (full number, `Cache-Control: no-store`) | 404, 503 |
| `GET /api/requests` | `status`, `emergency=true`, `bloodGroup`, `ids=a,b,c` (up to 50), `mine=1` (needs sign-in), `page`, `pageSize` | `{ requests: RequestDto[], total, page, pageSize }`, emergency first then newest | 401 (`mine`), 503 |
| `GET /api/requests/[id]` | optional `X-Manage-Token` | `{ request, responses: ResponseDto[], canManage: boolean }` (responder phones only when `canManage`) | 404, 503 |
| `POST /api/sos` (exists) | + optional `patientName`, `patientAge`, `attendantName` | 201 `{ id, manageToken }` (the token is shown once; only its hash is stored) | 400, 503 |
| `PATCH /api/requests/[id]` | `{ status }` | `{ request }` | 400, 401/403 (not allowed), 404, 409 `invalid_transition`, 503 |
| `POST /api/requests/[id]/respond` | `{ name, phone }` | 201 `{ response, status }` | 400, 404, 409 `already_responded` / `request_closed`, 503 |

Pagination: `page` starts at 1; `total` is the number of matching rows.

## Review focus (checked in the tasks below)
1. Anonymous request creator can complete or cancel their own request with the token, and nobody else can (wrong, missing, or another request's token).
2. A donor's full phone number never appears in the list response or the page source, only via `contact`.
3. Status transitions cannot skip the table (COMPLETED to PENDING is rejected), including two updates racing.
4. The same phone cannot respond twice to one request; closed requests reject responses.
5. Without a database every screen still shows sample data and nothing crashes.
